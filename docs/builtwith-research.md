# Как BuiltWith определяет технологии сайтов

Исследование по публичным страницам BuiltWith, 2026-11-04. Точные внутренние правила распознавания BuiltWith не опубликованы; ниже факты отделены от выводов.

## Что подтверждено BuiltWith

1. Результаты получаются автоматическим анализом **публично доступного кода сайта и инфраструктуры** по сигнатурам. BuiltWith прямо предупреждает о ложных срабатываниях из-за неиспользуемого кода, старых следов технологии и задержек индексации. [Terms of Use, раздел 12](https://builtwith.com/terms).
2. Их Domain API может вернуть профиль из базы или выполнить посещение сайта (`IsDB`), группирует технологии по пути и поддомену, хранит `FirstIndexed`/`LastIndexed`, а для технологии — `FirstDetected`/`LastDetected`, категорию, описание и confidence. [Domain API](https://api.builtwith.com/domain-api).
3. Профили содержат не только CMS и JavaScript-библиотеки: в публичных примерах видны хостинг, CDN, SSL, DNS, серверное местоположение, аналитика и другие категории. [Пример профиля](https://builtwith.com/wds-usa.com).
4. Confidence в API v26 — число от 0 до 1. В документации описаны понижения для однократного обнаружения, припаркованных доменов и некоторых подозрительных сайтов. Это **их собственная шкала**, её нельзя напрямую приравнивать к нашей «низкая/средняя/высокая». [Domain API: Technology Confidence](https://api.builtwith.com/domain-api), [пояснение к шкале](https://kb.builtwith.com/general-questions/confidence-score/).
5. Их браузерное расширение открывает технологический профиль сайта в BuiltWith; публичная страница расширения не описывает локальное сканирование страницы в браузере. [Browser Extensions and Widgets](https://builtwith.com/toolbar).

## Вывод об архитектуре

Судя по полям API, BuiltWith сочетает повторное индексирование доменов и страниц с сигнатурами разных типов, сохраняет историю и отображает текущие и прошлые находки. Это **вывод из опубликованного формата данных**, а не описание их закрытой реализации. Мы не знаем полный набор сигнатур, частоту обхода и точный алгоритм сопоставления.

## Что полезно нашему расширению

- Оставить локальный анализ текущей страницы как базовый режим. Для каждого результата хранить тип улики, короткое описание, дату анализа и уровень уверенности.
- Отделить находку **на текущей странице** от вывода **о всём домене**: чужой виджет или CDN на одной странице не доказывает, что весь сайт построен на этой платформе.
- При повторных экспортах сравнивать находки и отмечать «видно сейчас», «было раньше», «не подтверждено повторно».
- Добавлять анализ инфраструктуры только отдельным режимом и после оценки разрешений Chrome, сетевых запросов и приватности.
- В отчёте всегда показывать ограничение: скрытые серверные компоненты могут не оставлять публичных признаков.

## Ограничение для интеграции

BuiltWith предоставляет API по ключу, но их условия ограничивают использование данных для создания конкурирующих продуктов и баз технологических профилей. Перед любой интеграцией нужна отдельная проверка лицензии и условий именно для задуманного сценария. Для нашего локального детектора использовать собственные правила и публичные технические признаки, без копирования базы BuiltWith. [Terms of Use, разделы 6–8](https://builtwith.com/terms), [Domain API: Terms of Use](https://api.builtwith.com/domain-api).
